# 后台每日汇总、预生成报表与可用快照

日期：2026-11-26。状态：用户已确认采用此架构，新会话按本方案实施并自验。本会话仅完成交接，不实施业务逻辑、不写数据库。

用户确认依据：“可以，按照这种设计……生成提示词，我在新会话开始实施开发”。对应的上一轮设计：后台维护成员每日汇总；常用范围提前生成；60秒只作为刷新窗口；过期先返回可用旧报表；首次初始化后台构建；自定义日期从日汇总计算；不适用的旧权限快照不可继续返回。

本文件替换早期“首次请求或缓存过期时扫描全部原始数据”的设计，和[查询契约](QUERY_DESIGN.md)共同生效。以下存储名、并发限额和轮询间隔属于可自主细化的技术方案，不能以此要求用户再次确认架构。

## 1. 三层数据

| 层 | 数据与用途 | 维护方式 |
| --- | --- | --- |
| 原始事实镜像 | 现有工时source/entry与code_commit、identity、scan状态 | 沿用现有采集，不增第二套CODING扫描 |
| 统计日汇总 | 每组织/成员/北京时间日期的工时、有效工作日标记、加班，以及代码次数/新增/删除、分指标覆盖状态和来源版本 | 后台按受影响成员日期或代码月份重建，原子发布 |
| 已发布报表 | 日期/比较区间的全成员指标、各metric排名、均值与覆盖信息，不含个人化myPosition | 后台预生成或从日汇总异步构建；同版本派生Top10/分页/本人名次 |

所有统计数据可由镜像重建，不写回CODING。完整0值必须由覆盖事实确认后存为0，不用“没有汇总行”代表0。工时和代码完成时间/版本独立保存，不能工时已齐就宣称代码也齐。

## 2. 建议持久化实体与字段

具体表名与字段由实施会话结合数据库规范定稿，至少覆盖以下能力，形成独立迁移脚本和初始化DDL：

- external_zhaogang_statistics_day：coding_team_id、coding_user_id、stat_date；worklog_hours、eligible_workday、overtime_hours、overtime_days；commit_count、additions、deletions（changed_lines可派生）；各域/指标coverage/status/reasons；source/data/identity/calendar/leave/visibility/formula版本、published_generation、更新时间。工作/代码可物理拆表，只要同一指标按其版本原子可读。
- external_zhaogang_statistics_refresh_task：组织、任务种类/成员日或月份/报表范围、目标版本、唯一去重键、状态、priority、lease_id/lease_until、attempt、next_retry_at、rerun_requested、safe_error、时间戳。支持幂等、重启恢复、有限退避；状态不是只放进程内存。
- external_zhaogang_statistics_report：组织、规范化日期和比较区间、schema/formula/visibility与日汇总版本、snapshot_id、payload、generated_at、最后成功时间、需要更新标识及当前刷新状态。保留最近仍适用的已发布payload，构建中的候选结果隔离，事务切换当前指针。

同一个组织/规范范围/版本的任务合并；进行中又有新变更，记录下一目标版本，当前任务不能把新变更当成已完成。采用有界worker，建议最多1—2个并行统计构建，独立于远端扫描线程，避免影响原有工时采集。超时租约重试必须有fence令牌，旧worker不能覆盖新版。

不要每次刷新累计无限版本。发布后清理明确不再引用的旧候选/任务；保留至少最近可用报表，失败时不清空。自定义范围快照按容量/最近使用清理，避免任意区间组合无限持久化；正在使用的snapshot失效时走可恢复的整体重读协议。

## 3. 变更触发与补偿

当前源码集成线索：

- 工时WorklogMirrorRepository.publish成功发布后，通知对应成员及受影响StartAt区间；删除/回扫消失也必须反映。WorklogRegistered只表示远端登记已接受，不能以此虚构镜像已包含新增记录。
- 代码CodeScanWorker/CodeScanService在扫描发布、diff补算、同步结果及版本更新处登记受影响月份。沿用CodeContinuousSyncScheduler，不另起全组织CODING采集。
- Git身份增删/变更影响历史归属，需后台重算受影响成员/身份涉及月份；角色、成员、忽略开关与团队解散影响人口及历史规则。
- 日历/请假变更影响历史分母和加班分类，重算受影响日期；北京时间跨日刷新快捷范围与截至昨天口径。

事件应在事实事务成功提交后生效。事件投递失败不能把已成功登记/同步对外变成失败。用持久脏标记/事务outbox或等价补偿确保不丢更新；启动时和定时版本对账作为兜底，不能只依赖可能丢失的本地事件或Redis计数。刷新任务失败保留dirty版本，下轮重试，不推进已构建版本。

工时可按成员日期重算。代码应从同组织当前团队作用域的提交并集去重后生成日汇总；以受影响月份有界重算最容易保证删除/身份变化正确，不能将各团队日汇总直接相加。50人90天的最终日汇总量约4500行，是量级示意，不是实际性能验收。

初次回填从已有本地镜像开始，优先构建本月/本周，再补其他已采集历史月份（原工时起点和代码保留窗口保持不变）。镜像尚未采齐则统计区间保留未完成状态，不为统计页另行调取CODING。后台任务和日汇总版本共同表达已完成覆盖。

## 4. 预生成与请求行为

预生成范围至少包括页面提供的本周、上周、本月、上月、本季及对应上期。不同周期按规范化key共享报表，不因为role/keyword/pageNumber不同重复构建。切榜指标从同报表的全部metric结果派生，不重读原始事实。

| 情况 | HTTP返回 | 后台行为 |
| --- | --- | --- |
| 已有新鲜报表 | 正常hasData=true、IDLE | 不重复入队 |
| 超过60秒更新窗口，有仍适用旧报表 | 立即返回旧payload、stale=true、QUEUED/RUNNING | 仅一次更新，成功后原子替换 |
| 正常更新失败但旧报表仍适用 | 保留旧payload、FAILED与安全原因/原生成时间 | 有限重试，用户可点刷新；不推进成功时间 |
| 首次无日汇总/无快照 | 立即hasData=false、INITIALIZING/QUEUED | 调度本地构建，页面轮询，不等待扫全库 |
| 自定义日期初次请求 | 已有报表则读；未有则快速构建状态 | 从成员日汇总生成，缺日汇总先补后台任务 |
| Redis不可用/重启 | 从持久report读取 | 必要时补热缓存，不把原始表回填转到请求内 |
| 权限/成员/删除等强失效 | 撤下不再适用数据、返回准备中或当前合法缺失态 | 优先重建，不服务旧权限结果 |

单GET report入口保留，可以返回任务状态和report引用；轮询相同入口不重复排队。若项目规范选择独立轻量状态接口，允许实现时增加，业务行为不变。正常report GET不做远端调用；调度元数据写入须幂等有界。

用户点刷新只请求本地统计异步更新，继续返回旧适用报表及更新中状态；若数据版本未变化可快速完成并更新时间，不能假造CODING同步时间。60秒不是“强制删数据”的TTL；前端显示generatedAt、工时syncedAt、代码syncedAt及stale/refresh状态，几个时间不能混用。

## 5. 原子发布和强失效

区分两种版本变化：

- 新增登记、普通同步完成等新鲜度变化：允许读取上一版仍合法报表，异步追赶。
- 凭证/来源权限撤销、人员移除/排除、身份撤销、明确删除工时/事项等变化，以及会导致口径错误的角色/日历/请假变更：强失效，不继续展示受影响旧数据。

强失效需由事实写入路径与持久版本/脏标记可靠关联，请求只做轻量状态检查，不扫原始记录。不能仅靠Redis可能失败的自增实现安全失效。当前worker构建期间版本变化时发布前校验，旧任务不得重新发布已撤销数据。

日汇总重建必须处理“此前有值而本轮变0/未知/移除”：显式替换、清零或失效旧行，不能只UPSERT当前查到的非零数据。批量写候选后切版本/事务发布，读者不能看到半个月新数据加半个月旧数据。报表绑定实际日汇总版本；有变化时重算两期，不能只刷新本期留下上期旧名次。

允许工时/代码来自不同成功采集时间，各指标覆盖独立。不完整数据仍可显示安全已采集信息，但正式均值/排名资格按QUERY_DESIGN执行。强失效可以撤下整份报表而不强行局部修补，以保证不泄漏与一致性。

## 6. 迁移、回填和恢复

实施会话先编写和审查DDL/迁移，再在获授权的隔离本地测试库执行。至少有唯一键（组织/成员/日期或generation）、任务去重索引、组织/日期读取索引、report规范范围唯一引用；核对字段精度与最大payload、MySQL实际版本和索引计划。

执行顺序：确认连接确为本地/测试且保存必要备份 → 检查同名表/列结构 → 增量创建派生表/索引（禁止覆盖式重建原始业务表） → 检查唯一键/索引 → 启动后台构建 → 验证日汇总和report发布 → 执行可重复步骤的幂等复验。遇到结构冲突、目标环境不明、越界修改或断言不符立即停止该数据库步骤，继续其他可行验证。

故障恢复以暂停/禁用新统计worker、保留旧业务及原始镜像为先；清理仅限本次明确标记的派生候选/夹具。不要在未确认数据来源时DROP现有表；生产迁移只产出脚本和前置/停止/恢复说明，生产执行没有授权。

如使用用户本地现有数据库做自验，只能创建/维护本功能派生统计表及已声明的独立夹具，不能改真实成员角色、真实工时或真实CODING记录。更优先使用隔离MySQL测试schema；建schema权限不足时选择受支持的本地测试设施并记录，不能静默连生产。
