## 1. 查询流水线

重计算在后台完成：现有工时镜像发布/代码扫描与diff更新成功 → 登记受影响日期/月份 → 更新全员去重成员每日汇总 → 预生成常用报表 → 原子发布新snapshot。

请求链路只做有效会话与组织边界检查、轻量可见性/语义版本检查、读取已发布报表或小规模每日汇总、排序/搜索/分页派生。不能在首次请求、60秒过期、刷新或Redis不可用时同步扫描全部原始工时与提交。

- 有可用快照：立即返回；超过刷新窗口时合并安排后台更新，旧快照仍可读，新版成功后替换。
- 首次无快照/每日汇总未就绪：快速返回INITIALIZING/QUEUED与任务状态，后台构建，前端有界轮询。
- 自定义日期：从已发布成员每日汇总构建，不回扫原始表；初次报表未就绪可快速返回构建状态，后续轮询取得报表。
- 权限撤销、成员排除、身份撤销、删除事实等导致旧快照不再适用时，不可继续返回旧数据，先撤下受影响结果并后台重建。

范围只包含当前单一CODING团队下全部DevHub团队成员，不受本人加入列表限制。只返回统计资料，不返回工时描述、提交message、邮箱哈希或凭证。细节见后台方案。

## 2. 成员纳入与有效样本

建议同一成员任一团队关系ignore_team_statistics=false即参与；所有所属团队都为true则排除。当前参与集合用于当前期和上期，按当前角色回算历史，与原页现行规则一致。成员离开所有团队后退出此页；不建立历史编制/绩效档案。

工时样本为参与成员；代码样本为其中当前前端/后端开发。完整0值仍参与均值分母，不能只以活跃成员作分母。成员总数/参与数/排除数为组织范围事实，不因数据失败缩减。

每个指标具有value、status、reasonCodes和sampleCount/targetCount。status区分READY、PARTIAL、UNAVAILABLE、NOT_APPLICABLE。只有完整样本参与该指标正式排名与均值。若存在缺样本，卡片保留有效样本结果但状态标记部分，并可悬停了解有效人数；不能静默称完整全员均值。零有效样本或零分母显示—。

## 3. 四张卡片公式

设H_i为成员区间总工时、D_i为该区间内扣除请假的应出勤工作日、O_i为加班时长、T_i为加班天数；C_i为去重有效提交次数、A_i为新增行数、R_i为删除行数、L_i=A_i+R_i。

| 卡片 | 数值 | 建议公式与样本 |
| --- | --- | --- |
| 参与统计人数 | 人数 | 去重后参与集合人数；辅文全部人数、排除人数 |
| 工时情况 | 人均日工时 | 工时完整且D_i>0成员的ΣH_i/ΣD_i；2位小数，值旁小字“人均日工时” |
| 加班情况 | 人均加班天数、人均加班时长 | 工时完整成员的ΣT_i/人数、ΣO_i/人数；为整个所选周期均值，非每日值 |
| 代码情况 | 人均提交次数、人均提交行数 | 对应指标完整的开发成员：ΣC_i/次数有效人数、ΣL_i/行数有效人数；分母可以因diff异常而不同，分别返回样本数 |

人均日工时采用应出勤人日加权；不能简单平均先四舍五入过的个人日均值。分子沿用现有总登记工时（含休息日），所以可能超过8h；D_i=0者不参与此日均值，但其已完整取得的工时和加班仍可在其他适用指标展示。平均值以BigDecimal计算，最后展示时舍入；天数可1位小数，时长/次数均值2位小数，代码行均值保留合理精度。

卡片公式说明与有效样本可通过卡片普通悬停提示，不新增“提交行数”标签信息图标，也不把用户要求删除的辅文重新加回画面。

## 4. 工时后台汇总与计算

后台汇总任务新增批量只读入口，内部复用WorklogMirror的来源选择/可见性判断和WorklogMirrorRepository的有效记录过滤：current source、blocked=0、missing=0、区间StartAt，排除deleted_entry/deleted_issue/deleted_issue_key。不能直接绕过现有过滤对原始表SUM。

按成员+北京时间日期在SQL预聚合SUM(hours)，补齐区间有效日历中的0工时日；仅已验证完整的成员才补0。StartAt为毫秒，Java以Asia/Shanghai生成[from 00:00,to+1 00:00)边界；SQL日期分桶明确UTC+8，不依赖数据库会话时区。

将日数据交给原工时规则共用的纯计算组件，必要时从现有私有方法提取，不复制两份算法：

- 利用率=H_i/(D_i×8)×100，允许>100%，最终2位小数；D_i=0显示—。
- 工作日超8h部分为加班，≥9h记1个加班日。
- 休息日全部时长为加班，≥4h记1个加班日。
- 个人请假扣分母，仍按原工作日/休息日规则处理当天实际工时，不把请假日自动变成休息日加班。

来源失效、历史未补齐、过旧、缺字段等沿用WorklogMirror.problem及现有规则。不要为让本月更快“变完整”在新模块绕过现有历史初始化判定。工时数值与原页同区间同成员口径可核对。

## 5. 代码后台汇总与计算

由后台任务批量读取同组织全部当前团队WORKBENCH_TEAM作用域的扫描状态、必要提交字段及成员身份集合；不额外混入个人SELF提交快照。采用窄字段投影/有界分批读取，不拉message、分支JSON、文件分类JSON或完整diff。

当前CodeIdentityResolver已将成员SELF身份作为唯一身份集合；新增批量identity读取入口，复用现有mappingIndex/resolve规则，避免对每人调用一次selectByScope。冲突/未归属保留未知状态，不自行改成“只要邮箱匹配就强行归属”。

先按(codingTeamId,depotId,sha)跨团队去重，再以全员身份解析成员。相同SHA出现在多个分支不重复；不同depotId仍按现有仓库粒度分别计。提交作者/时间等重复记录不一致时单列冲突，不能按团队顺序任取。

C_i=去重后可信归属该成员的非Merge提交数量。A_i/R_i只累计成功有效diff；L_i=A_i+R_i，删除行取正数量，不做净增相减。

沿用CodeLinePolicy：online.base.apijar.service只计提交次数，不计任何行数；属于既有主动排除，不冒充diff异常。其他仓库diff失败/缺失时，该成员行数指标不完整，不按0。提交集合已完整时仍可参加提交次数榜。重复记录一份diff成功、一份暂缺，可使用成功有效结果一次；多份成功结果冲突则受影响指标不完整。

完整性必须结合本组织团队扫描范围、任务/仓库状态、凭证可见性和身份解析判断，不能仅因为表内查到几条提交就宣称该成员完整。尚未建立仓库覆盖或未知作者导致无法定位受影响人员时，保守标记相关代码范围不完整，避免错封冠军。

不新增一套全员CODING扫描任务；复用现有后台调度，补齐团队发现及读状态的批量能力。正常查询不触发CODING请求或任务重扫，也不扫描原始代码表；后台成员日汇总才读取上述原始提交。

## 6. 榜单、表格与上期

工时metric：UTILIZATION_RATE、TOTAL_HOURS、OVERTIME_HOURS、OVERTIME_DAYS。
代码metric：COMMIT_COUNT、CHANGED_LINES、ADDITIONS、DELETIONS。没有活跃天数控件和返回展示列。

每个metric单独判断资格并在全体适用成员中排名，同值并列1、2、2、4；利用率用最终2位值判并列，其余按原始指标。相同名次用稳定userId排序，先全局排名再Top10/分页。第10条并列者超出图表时保留同名次并注明并列，不改成独占第10名。

两榜metric独立；表格有独立sortMetric，默认利用率。姓名搜索、角色过滤作用于表格显示，rank及rankDelta保留全局。无资格行仍可在表中查看，rank=null并给原因；完整0值参与排名，但全0不突出冠军。本人不受当前分页搜索影响，myPosition返回其本榜名次或不适用/异常原因。

13列按主文档顺序返回。数据状态包含domain、reasonCode、safeMessage、affectedMetrics。示例diff失败提示“部分提交的代码行数同步失败；提交次数已同步，代码行数暂不可用”。悬停直接展示返回的安全短文案，不显示原始堆栈、仓库路径、个人凭证或管理令牌信息。

上期建议：完整自然周/月对上一周/月；本月截至昨天对上月同进度；自定义对前一等长区间。前端传rangeKind表达快捷范围语义，由后端返回明确的comparisonRange，不只凭from/to猜是自然月还是自定义。上月无对应日期时标不可比并说明，不补0。两个周期使用同一当前成员/资格集合，任一期缺数据或入榜集合不同则不生成正式升降名次。

rankDelta=上期名次-本期名次，正值前进；表格“较上期”对应当前sortMetric，两榜底部对应自身metric。不是工时增长率，也不是综合排名变化。

## 7. 拟新增接口

推荐先用单一报表入口，保证初次页面卡片、双榜、本人位置和表格来自同一计算版本，而不是独立并发读取几份可能错位的快照。

GET /external-service/api/zhaogang/statistics/report

参数：from/to（含首尾）、rangeKind、worklogMetric、codeMetric、sortMetric、sortOrder、keyword、role、pageNumber、pageSize、compare、可选snapshotId、refresh。refresh只安排异步本地统计刷新并保留适用旧报表，不等待全量计算；60秒为更新窗口而非结果存活期限。默认工时利用率/提交次数/表格利用率降序，pageSize=10（允许调整但设上限）。不接受scope、workbenchTeamId、codingTeamId或用户ID集合。

返回结构：

```json
{
  "range": {"from": "2026-11-01", "to": "2026-11-25"},
  "comparisonRange": {"from": "2026-10-01", "to": "2026-10-25"},
  "snapshotId": "opaque-id",
  "hasData": true,
  "refresh": {"state": "IDLE", "stale": false, "jobId": null, "generatedAt": null},
  "population": {"total": 56, "participating": 54, "excluded": 2, "developers": 38},
  "summary": {},
  "worklogRanking": {"metric": "UTILIZATION_RATE", "items": [], "myPosition": {}, "coverage": {}},
  "codeRanking": {"metric": "COMMIT_COUNT", "items": [], "myPosition": {}, "coverage": {}},
  "members": {"items": [], "page": {}},
  "dataStatus": {"worklogSyncedAt": null, "codeSyncedAt": null, "affectedMemberCount": 0}

```

响应还需支持hasData=false且snapshotId=null的首次构建状态；summary/榜单/表格此时为null，不返回虚假零值。refresh.state为IDLE/QUEUED/RUNNING/FAILED/INITIALIZING。覆盖完整性、报表新鲜度及任务状态是三件事，不能共用一个partial开关。数字仅为结构示例，不能作为接口验收事实。summary每个指标携带value/status/有效人数/目标人数；members每行携带原值、rank、rankDelta、比较失败原因与安全状态原因。完整0用0，未知/不适用用null+status，不用空字符串混淆。

## 8. 一致性、缓存与交互

用户已接受的最终设计是持久化成员每日汇总+可读旧快照+后台更新；详见[后台汇总与快照方案](STORAGE_AND_REFRESH.md)。旧方案中“冷查询扫原始表、缓存失效即丢结果、refresh同步重算”的行为已经替换，不能实施。

报表按组织、区间、比较区间、人口/成员/排除/角色、来源/删除/身份、日历/请假和公式版本绑定。后台构建读取一致版本，发布前校验租约及当前可见性/语义版本；失败保持上一份仍适用快照，禁止半成品覆盖。

Redis可作为热缓存，但日汇总、刷新任务、最近已发布报表要有持久恢复能力；Redis重启/丢失时从本地持久结果读取，不能把全量重建推给HTTP请求。正常60秒新鲜度过期不删除已发布报表。

snapshotId不能替代授权；每次请求检查会话及轻量版本，强失效后撤下旧结果，不为视觉连续性继续暴露。原始数据新增/普通同步变更属于可异步追赶的新鲜度变化；凭证/成员/身份删除、明确删除工时等属于必须及时阻断的变化。

切换榜单指标/排序/分页从同一报表派生，不重复扫日汇总或原始表；本人位置按会话动态生成。旧snapshot确实失效时保留筛选并整体重读，不拼接旧页码的数据。用户点刷新时有旧报表则保留并显示更新中，无旧报表显示准备中；刷新失败有原因及重试，不把旧数据更新时间推进为本次成功。

前端有界轮询后台状态（建议3—5秒，仅页面可见且有进行中任务时），成功后原子替换整份报表，失败停止并可重试；关闭页面/切日期/账号取消旧轮询或丢弃迟到响应。轮询不重复排队。午夜按北京时间更新已结束日期，旧区间的结果不能冒充新的默认本月区间。

姓名/角色筛选仅影响表格，不影响四卡和双榜。首次、完整零值、数据异常、统计准备中、旧数据更新中、刷新失败使用不同状态。

按已确认方案新增必要的可重建统计日汇总、持久任务与报表快照存储，不改CODING事实来源。工时在后台按成员日SQL预聚合；代码在后台只取窄字段、分批去重归属，再生成成员日汇总。HTTP只从已发布报表派生排名分页；构建报表时从日汇总计算O(N log N)排名。查询不得按每个团队/每个成员发起HTTP或数据库N+1。现有代码索引以scope/date为主；实施时EXPLAIN验证全局查询，必要时增加针对日期/仓库SHA的索引。是否新增索引由真实数据执行计划决定，不预先承诺零迁移或具体耗时。

日期默认本月截至昨天。北京时间from含首日、to含末日，内部统一半开区间；rangeKind不能与真实日期矛盾。单次最多366天，未来日拒绝，工时2026-01-01之前及代码保留窗口外明确不可用。分子、分母、上期覆盖均单独校验。
