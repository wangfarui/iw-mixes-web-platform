# 迭代人工事项与 CODING 补链验收

验证日期 2026-11-10。Web 通过本地开发服务运行，迭代和 CODING 接口使用独立的内存模拟数据。数据库验证使用一次性 MySQL 8.0 容器及项目实际的 MyBatis 仓库代码。

| 用例 | 结果 | 操作与观察 |
| --- | --- | --- |
| AC-01 人工新增顶层事项 | 通过 | 浏览器在空迭代展开类型选项，显示需求、任务、用户故事、子工作项、缺陷。实际保存需求与缺陷，显示为工作台事项。后端参数化测试覆盖五种类型，仅写工作台。 |
| AC-02 父事项未绑定 | 通过 | 测试用户偏好开启自动同步。新增用户故事时开关禁用，浏览器请求提交 `syncToCoding: false`。后端测试覆盖调用方显式请求同步及更上层已有链接的情况，子事项仍保存为 `NOT_REQUIRED`。 |
| AC-03 补绑已有 CODING 事项 | 通过 | 浏览器模拟类型不匹配时保留链接输入，重试后原事项显示 CODING 编号和状态。后端测试验证拒绝类型不符、重复关联和二次绑定。隔离 MySQL 验证绑定沿用原 ID 和父子关系，并拒绝补链前提交的过时编辑。 |
| AC-04 补链后新增子事项 | 通过 | 浏览器显示同步开关恢复并按偏好默认勾选，提交 `syncToCoding: true`。原有本地故事仍显示为工作台事项。后端模拟 CODING 测试验证请求指向正确的远端父事项。 |
| AC-05 状态回写与批量回拉 | 部分通过 | 浏览器状态下拉触发正确的状态更新请求。后端模拟 CODING 验证 `ModifyIssue` 回写和已补绑缺陷回拉。隔离 MySQL 验证批量更新快照后保留工作台父子关系和来源。真实 CODING 尚未联调。 |
| AC-06 已有数据库迁移 | 通过 | 在隔离 MySQL 对旧事项表执行增量 SQL，历史行获得默认标记 `0`。当前初始化 SQL 创建的事项表使用相同默认值。 |

- 后端 `iw-external` 共 369 项测试通过，其中迭代模块 80 项。Web 迭代专项测试、类型检查和生产构建通过。
- 模拟浏览器数据和隔离 MySQL 数据仅用于本次验证。已有环境部署前需执行 [人工事项补链迁移](../../../../iw-mixes-server/iw-packaging-parent/iw-external/scripts/iw-external-migrate-20261110-iteration-manual-link.sql)。


## CODING 字段选项补充验证

AC-07 通过。浏览器模拟无 CODING 关联事项的迭代，直接打开子事项表单即可加载开发团队、DoD 和任务类型下拉。DoD 默认选中「上线完成」，测试角色创建子工作项默认选中「测试任务」。两次保存均提交 `syncToCoding: false`，重新编辑用户故事可回显。后端测试覆盖迭代项目优先、可访问项目自动补齐和缺少对应事项类型时继续查询。实际 CODING 项目字段尚未联调。


## 首次补链回拉字段

AC-08 通过。后端测试验证首次绑定读取 CODING 标题、状态、描述、开发团队、DoD、子工作项任务类型和预估工时，且绑定过程只读 CODING。隔离 MySQL 验证链接和字段在原事项行内写入，CODING 空 DoD 清除已有值，原 ID、父子关系、既有子事项和需求原型链接继续保留。真实 CODING 字段回拉尚未联调。

AC-09 通过。子工作项补链直接读取 CODING 工时，后端测试覆盖 2 次 / 1.75 h、0 次 / 0 h 和读取失败保留未关联状态。隔离 MySQL 验证工时快照随链接写入原行，零值能覆盖旧汇总。后端 377 项测试通过，真实 CODING 项目尚未联调。
