## 实测性能

HTTP 耗时由本机客户端计量，生成耗时从首次返回状态起轮询至可读，含等待调度与优先快捷任务的时间。单次样本只表示该次观察。

| 场景 | 样本 | HTTP p50 / 最大 | 后台排队至可读 |
| --- | ---: | --- | --- |
| 首次自定义范围 | 1 | 18.42 ms | 3.03 s |
| 同一范围热读 | 30 | 17.12 / 26.07 ms | — |
| 超过 60 秒并发读旧快照 | 16 | 88.60 / 103.85 ms | 1.38 s |
| 自定义 90 天 | 1 首次、15 次切指标或页码 | 首次 16.33 ms，热读 16.48 / 17.75 ms | 7.75 s |
| 自定义 366 天 | 1 首次、15 次切指标或页码 | 首次 19.20 ms，热读 15.98 / 18.54 ms | 5.38 s |
| 注入失败后手动恢复 | 1 | — | 1.42 s |
| 删除后撤下旧结果及重建 | 1 | 16.57 ms | 1.95 s |
| Redis 不可达 / 恢复后 | 各 1 | 21.92 / 17.67 ms | 已有 MySQL 快照 |

隔离 MySQL general log 对 HTTP 所用连接计数，排除事务控制语句。单次热读 8 条 SELECT，其中 6 条是业务与授权查询。一次冷读 11 条 SELECT/INSERT，其中 10 条作用于统计与授权表。两次皆无工时明细、工时来源或原始提交表读取。CODING 夹具仅收到账户绑定与 Dev Hub 壳层的请求。

[关键 EXPLAIN ANALYZE](mysql-explain.txt) 包含实际查询及去标识样本。工时走 `idx_worklog_page` 时间索引，排除三个删除表中的记录。扫描提交按 `idx_org_month_depot_sha` 推进；跨月 SHA 冲突查询从初验逐条扫表改为 `idx_org_depot_sha` 覆盖查找，实测每次查找约 1.07 行。日汇总范围走主键，热报表主键只定位一行。
